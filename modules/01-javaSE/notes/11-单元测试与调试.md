# 11-单元测试与调试

> 预计用时：3～4 小时（读笔记 1.5 小时 + 做练习 1.5～2 小时）

## 本课目标

1. 理解单元测试的价值
2. 会用 JUnit 5 写测试：`@Test`、断言、`@BeforeEach`
3. 会处理"测试失败"，看懂断言信息
4. 掌握 IDEA 断点调试的基本操作
5. 能独立定位并修复一个 bug

---

## 1. 为什么需要单元测试

- **回归保障**：改了一个功能，跑一遍测试就知道有没有改坏别的地方
- **文档作用**：测试代码就是"这个类应该怎么用"的活文档
- **驱动设计**：先写测试再写实现（TDD），逼你想清楚输入输出

没有测试的项目，改代码全靠"感觉"，越改越不敢动。

## 2. JUnit 5 快速上手

### 2.1 环境

命令行学习阶段，用官方提供的"独立 jar"（包含 JUnit 全部组件，不需要 Maven）：

```powershell
cd modules\01-javaSE\exercises\lesson11
New-Item -ItemType Directory -Force lib | Out-Null
Invoke-WebRequest -Uri "https://repo1.maven.org/maven2/org/junit/platform/junit-platform-console-standalone/1.12.2/junit-platform-console-standalone-1.12.2.jar" -OutFile "lib\junit-platform-console-standalone.jar"
```

（IDEA 里用 Maven 的，后面 Spring 阶段会学。）

### 2.2 第一个测试

```java
package lesson11;

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {

    @Test
    void addShouldReturnSum() {              // 方法名用"行为描述"
        Calculator calc = new Calculator();
        int result = calc.add(2, 3);
        assertEquals(5, result);             // 断言：期望值在前，实际值在后
    }
}
```

### 2.3 常用断言

```java
assertEquals(5, result);                    // 相等（基本类型/对象 equals）
assertNotEquals(1, result);
assertTrue(result > 0);
assertFalse(result < 0);
assertNull(obj);
assertNotNull(obj);
assertThrows(ArithmeticException.class, () -> calc.divide(1, 0));  // 期望抛异常
```

**断言失败时的信息：** `expected: <5> but was: <4>` —— 期望值和实际值都告诉你，很好排查。

### 2.4 生命周期方法

```java
class CalculatorTest {

    Calculator calc;                          // 每个测试方法都用自己的实例

    @BeforeEach
    void setUp() {                            // 每个测试执行前运行（准备数据）
        calc = new Calculator();
    }

    @AfterEach
    void tearDown() {                         // 每个测试执行后运行（清理资源）
        // ...
    }

    @Test
    void addShouldReturnSum() { ... }
}
```

### 2.5 参数化测试（了解）

```java
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;

@ParameterizedTest
@CsvSource({"2,3,5", "0,0,0", "-1,1,0"})
void addShouldHandleMultipleCases(int a, int b, int expected) {
    assertEquals(expected, calc.add(a, b));
}
```

### 2.6 命令行运行

```powershell
javac -encoding UTF-8 -cp "lib\junit-platform-console-standalone.jar" -d out Calculator.java CalculatorTest.java
java -jar lib\junit-platform-console-standalone.jar --class-path out --scan-class-path
```

**测试命名规范：** 方法名用"行为描述"：`addShouldReturnSum`、`divideByZeroShouldThrow`。

## 3. IDEA 断点调试（重点技能）

**调试 = 让程序停在指定位置，一步步看变量变化。**

### 3.1 基本操作

| 操作 | 快捷键 | 作用 |
| --- | --- | --- |
| 打断点 | 点击行号左侧 | 程序运行到这里暂停 |
| 启动调试 | Shift+F9（Debug 按钮） | 以调试模式运行 |
| Step Over | F8 | 执行当前行，不进入方法内部 |
| Step Into | F7 | 进入方法内部 |
| Step Out | Shift+F8 | 跳出当前方法 |
| Resume | F9 | 继续运行到下一个断点 |
| 停止 | Ctrl+F2 | 结束调试 |

### 3.2 条件断点（很有用）

右键断点 → 输入条件（如 `i == 100`）→ 循环 1000 次时只在第 100 次停下。

### 3.3 调试窗口

- **Variables 窗口**：看当前所有变量的值
- **Watches 窗口**：添加表达式（如 `list.size()`），实时看变化
- **Evaluate Expression（Alt+F8）**：在暂停时执行任意表达式，改值、调方法都行

### 3.4 调试思路

1. 先确定"症状"：哪一步输出不对
2. 从可疑代码起点打断点，逐步跟进
3. 观察变量的值在哪一步开始不对 → 缩小范围 → 定位根因
4. 修复后**跑一遍相关测试**确认没改坏

## 4. 调试技巧补充

- **二分定位**：代码长时，在中间打断点，先判断前半段对错，再缩小范围
- **打印 vs 断点**：临时排查用 `System.out.println` 快，但记得删；复杂问题用断点更清晰
- **看堆栈**：异常发生时，堆栈从下往上就是"调用链"，先看最上面自己的代码行
- **不要猜，要看**：凭感觉改代码是调试大忌，用断点确认每一处假设


```text

可能的原因有哪些？怎么定位？
```

**让 AI 出调试题：**

```text

我用调试器找 bug，找到后你再确认。
```
