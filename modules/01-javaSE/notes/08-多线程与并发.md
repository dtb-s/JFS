## 1. 进程与线程

- **进程**：正在运行的程序，有独立内存空间
- **线程**：进程内的执行单元，**共享进程内存**

多线程的目的：让多个任务"同时"推进（下载的同时操作界面、服务器同时服务多人）。单核是时间片快速切换，多核才是真并行。

## 2. 创建线程

```java
// 方式一：继承 Thread（不推荐，浪费继承名额）
class MyThread extends Thread {
    @Override public void run() { System.out.println("运行：" + Thread.currentThread().getName()); }
}
new MyThread().start();

// 方式二：实现 Runnable（推荐）
new Thread(() -> System.out.println("任务执行中")).start();

// 方式三：Callable + FutureTask（有返回值）
FutureTask<Integer> task = new FutureTask<>(() -> 1 + 2);
new Thread(task).start();
Integer result = task.get();   // 阻塞等待结果
```

**start() vs run()（必考）**：`start()` 启动新线程并在新线程中执行 run；`run()` 只是当前线程的普通方法调用，**不会开新线程**。

## 3. 生命周期与常用方法

新建 → 就绪 → 运行 → 死亡，中间可在阻塞/等待之间切换（sleep、等锁、join、IO）。

| 方法 | 作用 |
| --- | --- |
| `sleep(ms)` | 睡指定毫秒，**不释放锁** |
| `join()` | 等该线程执行完，当前线程再继续 |
| `yield()` | 让出 CPU（只是建议，不一定生效） |
| `setDaemon(true)` | 守护线程，主线程结束即结束 |
| `interrupt()` | 中断线程（配合 InterruptedException） |

## 4. 线程安全（本课核心）

多个线程同时读写**共享数据** → 竞态条件。`tickets--` 不是原子操作（读、改、写三步），并发下会重复卖票甚至卖出负数。

```java
// 同步方法：锁是 this
public synchronized void sell() {
    if (tickets > 0) { tickets--; }
}

// 同步代码块：可指定锁对象，粒度更细
public void sell() {
    synchronized (this) {   // 也可以 synchronized (lockObj)
        if (tickets > 0) { tickets--; }
    }
}
```

- 同一时刻只有一个线程能进入被同一把锁保护的代码
- **静态同步方法锁的是类对象**（`Xxx.class`），与实例方法的 `this` 不是同一把锁，别混用
- `sleep()` 不释放锁，`wait()` 释放锁（wait/notify 生产者消费者模型后续深入学习）

## 5. volatile（了解）

保证**可见性**：一个线程改了变量，其他线程立刻看到最新值。

但**不保证原子性**：`volatile int count` 自增在多线程下仍会丢更新，计数场景要用 `synchronized` 或 `AtomicInteger`。

## 6. Lock（了解）

```java
Lock lock = new ReentrantLock();
lock.lock();
try {
    // 临界区
} finally {
    lock.unlock();   // 必须 finally 释放
}
```

比 synchronized 灵活：可超时、可中断、可有多个条件。

## 7. 线程池（重点，面试高频）

```java
ExecutorService pool = Executors.newFixedThreadPool(3);
pool.execute(() -> System.out.println("任务1"));   // 无返回值
pool.submit(() -> 1 + 2);                          // 可拿结果
pool.shutdown();                                   // 不再接收新任务，跑完已提交的再关闭
```

ThreadPoolExecutor 核心参数（背下来）：

```java
new ThreadPoolExecutor(
    corePoolSize,      // 核心线程数（常驻）
    maximumPoolSize,   // 最大线程数
    keepAliveTime,     // 非核心线程空闲存活时间
    unit,              // 时间单位
    workQueue,         // 任务队列
    handler            // 拒绝策略
);
```

任务流转：核心线程未满 → 建新线程；核心满了 → 进队列；队列满 → 建非核心线程；再满 → 走拒绝策略。

**阿里规范**：生产环境不要用 `Executors` 快捷方法（默认无界队列容易 OOM），要用 `ThreadPoolExecutor` 显式配置。

## 8. 并发容器（了解）

| 场景 | 容器 |
| --- | --- |
| Map | `ConcurrentHashMap`（首选） |
| List | `CopyOnWriteArrayList`（读多写少） |
| 队列 | `ArrayBlockingQueue`、`LinkedBlockingQueue` |

`Hashtable`、`Collections.synchronizedMap` 是全局锁、性能差，面试要能说出为什么不如 `ConcurrentHashMap`。
