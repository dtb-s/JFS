## 1. 进程与线程

- **进程**：正在运行的程序（如一个 IDEA 就是一个进程），有独立的内存空间
- **线程**：进程里的执行单元，一个进程可以有多条线程，**共享进程的内存**

**为什么需要多线程：** 让多个任务"同时"推进。比如下载文件的同时还能操作界面；服务器同时服务多个用户。单核 CPU 是快速切换（时间片），多核才是真并行。

## 2. 创建线程的两种方式

### 方式一：继承 Thread（不推荐，Java 单继承会浪费继承名额）

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("线程运行中：" + Thread.currentThread().getName());
    }
}

MyThread t = new MyThread();
t.start();      // 启动线程（自动调用 run）
```

### 方式二：实现 Runnable（推荐）

```java
class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("任务执行中");
    }
}

Thread t = new Thread(new MyTask());
t.start();
```

### 方式三：Callable + FutureTask（有返回值，了解）

```java
FutureTask<Integer> task = new FutureTask<>(() -> 1 + 2);
new Thread(task).start();
Integer result = task.get();   // 阻塞等待结果
```

### start() vs run()（必考）

```java
t.start();   // 启动新线程，新线程里执行 run
t.run();     // 没有新线程！只是当前线程直接调用 run 方法
```

## 3. 线程生命周期

```text
新建（new）→ 就绪（start 后等待 CPU）→ 运行（拿到 CPU）→ 死亡（run 结束）
                  ↑                    ↓
                  └── 阻塞/等待（sleep、等待锁、join、IO）──┘
```

**常用方法：**

| 方法 | 作用 |
| --- | --- |
| `sleep(ms)` | 当前线程睡指定毫秒（**不释放锁**） |
| `join()` | 等待这个线程执行完，当前线程再继续 |
| `yield()` | 让出 CPU（只是建议，不一定生效） |
| `setDaemon(true)` | 设为守护线程（主线程结束它就跟着结束） |
| `interrupt()` | 中断线程（配合 InterruptedException） |

```java
Thread t = new Thread(() -> {
    for (int i = 0; i < 3; i++) {
        System.out.println(i);
        try { Thread.sleep(100); } catch (InterruptedException e) { }
    }
});
t.start();
t.join();   // main 等 t 跑完再继续
System.out.println("t 结束了");
```

## 4. 线程安全问题（本课核心）

### 4.1 问题是怎么产生的

多个线程同时读写**共享数据**，就会产生竞争（race condition）。

经典卖票场景：

```java
class TicketWindow implements Runnable {
    private int tickets = 100;

    @Override
    public void run() {
        while (tickets > 0) {
            // 两个线程可能同时判断 tickets > 0，然后同时 tickets--
            System.out.println(Thread.currentThread().getName() + " 卖出第 " + tickets + " 张");
            tickets--;
        }
    }
}
```

三个窗口同时卖 100 张票，可能出现：同一张票卖出两次、卖成负数。因为 `tickets--` 不是原子操作（读、减、写三步，可能被插队）。

### 4.2 synchronized 解决

`synchronized` 保证**同一时刻只有一个线程**能进入代码块（需要先拿到锁）。

**同步方法（锁是 this）：**

```java
public synchronized void sell() {   // 整个方法加锁
    if (tickets > 0) {
        System.out.println(...);
        tickets--;
    }
}
```

**同步代码块（锁可以指定对象，粒度更细）：**

```java
public void sell() {
    synchronized (this) {           // 也可以 synchronized (lockObj)
        if (tickets > 0) {
            System.out.println(...);
            tickets--;
        }
    }
}
```

**静态同步方法锁的是类对象**（`TicketWindow.class`），和实例方法锁（this）不是同一个锁，注意别混用。

**注意：** `sleep()` 不释放锁；`wait()` 释放锁（wait/notify 是生产者消费者模型的基础，本课先了解，面试深挖时再学）。

## 5. volatile（了解）

`volatile` 保证**可见性**：一个线程修改了变量，其他线程立刻能看到最新值（不经过各自 CPU 缓存）。

```java
volatile boolean running = true;   // 其他线程读到的永远是"最新的"
```

**但它不保证原子性**，`volatile int count++` 在多线程下依然会丢更新。计数场景还是要 synchronized 或 AtomicInteger。

## 6. Lock 接口（了解）

JDK 5+ 提供的显式锁，比 synchronized 灵活（可超时、可中断、可多个条件）：

```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

Lock lock = new ReentrantLock();
lock.lock();
try {
    // 临界区
} finally {
    lock.unlock();   // 必须 finally 释放！
}
```

## 7. 线程池（面试高频，重点）

**为什么要线程池：** 每个线程创建和销毁都有开销；线程多了系统资源不够。线程池 = 提前创建一批线程循环使用。

**Executors 工厂（够用）：**

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

ExecutorService pool = Executors.newFixedThreadPool(3);   // 固定 3 个线程
// Executors.newCachedThreadPool();    // 弹性线程池
// Executors.newSingleThreadExecutor(); // 单线程

pool.execute(() -> System.out.println("任务 1"));   // 提交任务（无返回值）
pool.submit(() -> 1 + 2);                          // 提交任务（可拿结果）

pool.shutdown();   // 不再接收新任务，跑完已提交的任务后关闭
```

**ThreadPoolExecutor 核心参数（背下来，面试必问）：**

```java
new ThreadPoolExecutor(
    corePoolSize,      // 核心线程数（常驻）
    maximumPoolSize,   // 最大线程数
    keepAliveTime,     // 非核心线程空闲存活时间
    unit,              // 时间单位
    workQueue,         // 任务队列（排队等线程）
    handler            // 拒绝策略（队列也满时怎么办）
);
```

流程：任务来了 → 核心线程没满就开新线程 → 满了进队列 → 队列满了开非核心线程 → 都满了走拒绝策略。

**阿里规范提醒：** 生产环境不要用 `Executors` 的快捷方法（默认队列无界容易 OOM），要用 `ThreadPoolExecutor` 显式配置。

## 8. 并发容器（了解）

| 场景 | 线程安全容器 |
| --- | --- |
| Map | `ConcurrentHashMap`（分段锁/锁粒度细，首选） |
| List | `CopyOnWriteArrayList`（读多写少） |
| 队列 | `ArrayBlockingQueue`、`LinkedBlockingQueue`（生产者消费者） |

**注意：** `Hashtable` 和 `Collections.synchronizedMap` 是全局锁，性能差，**面试要能说出不如 ConcurrentHashMap 的原因**。
