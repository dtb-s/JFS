## 1. 什么是异常

程序运行时出现的错误，比如：除以 0、数组越界、文件不存在。Java 用**异常对象**来描述这些错误，并提供了处理机制，让程序"出错了也不至于直接崩溃"。

**异常体系：**

```text
Throwable（一切错误的总称）
 ├── Error（严重问题，程序无法处理）
 │     ├── OutOfMemoryError
 │     └── StackOverflowError
 └── Exception（程序可以处理的错误）
       ├── RuntimeException（运行时异常，非受检）
       │     ├── NullPointerException
       │     ├── ArrayIndexOutOfBoundsException
       │     ├── ArithmeticException
       │     └── ClassCastException
       └── 其他受检异常（编译期强制处理）
             ├── IOException
             ├── FileNotFoundException
             └── SQLException
```

**Error vs Exception：** Error 是 JVM 级别的问题（内存不够、栈溢出），程序不该也无法处理；Exception 是程序逻辑问题，应该处理。

## 2. 受检异常 vs 非受检异常（面试必考）

| 对比 | 受检异常（Checked） | 非受检异常（Unchecked） |
| --- | --- | --- |
| 父类 | Exception（非 RuntimeException） | RuntimeException |
| 编译期 | **强制**处理（try-catch 或 throws） | 不强制 |
| 代表 | IOException、SQLException | NPE、越界、除零 |
| 触发时机 | 外部环境问题（文件/网络/数据库） | 代码逻辑 bug |

```java
// 受检异常：不处理编译不过
Thread.sleep(1000);   // 编译错误：InterruptedException 必须处理

// 非受检异常：编译能过，运行期才可能炸
int x = 10 / 0;       // 编译通过，运行期抛 ArithmeticException
```

## 3. try-catch-finally

```java
try {
    int result = 10 / 0;          // 可能出错的代码
    System.out.println("这行不会执行");
} catch (ArithmeticException e) {  // 捕获特定异常
    System.out.println("除零了：" + e.getMessage());
} finally {
    System.out.println("无论是否异常都执行");   // 资源清理
}
```

**规则：**

1. **多个 catch 顺序**：子类异常在前，父类在后（先 `ArithmeticException` 再 `Exception`，否则子类永远捕不到）
2. `finally` **总会执行**（即使 catch 里 return 也会先执行 finally；除非 System.exit）
3. 经典面试题：try 和 finally 里都有 return，**finally 的 return 会覆盖 try 的**
4. 捕获后要处理（打印日志或抛出），**不要空 catch 吞掉异常**

**Java 7+ 多异常捕获：**

```java
try {
    // ...
} catch (ArithmeticException | NullPointerException e) {
    System.out.println("捕获到：" + e.getClass().getSimpleName());
}
```

## 4. try-with-resources（推荐，Java 7+）

**问题：** 传统写法必须手动 close，还要在 finally 里处理 close 自己的异常，啰嗦：

```java
BufferedReader reader = null;
try {
    reader = new BufferedReader(new FileReader("a.txt"));
    System.out.println(reader.readLine());
} finally {
    if (reader != null) reader.close();
}
```

**try-with-resources：** 实现 `AutoCloseable` 的资源，用完后自动关闭：

```java
try (BufferedReader reader = new BufferedReader(new FileReader("a.txt"))) {
    System.out.println(reader.readLine());
}   // reader 自动 close，无需 finally
```

多个资源用分号分隔：`try (A a = ...; B b = ...)`。**日常写代码优先用这个。**

## 5. throws 与 throw（两个易混的关键字）

| 关键字 | 位置 | 作用 |
| --- | --- | --- |
| `throws` | 方法声明上 | 声明"这个方法可能抛出什么异常"，交给调用者处理 |
| `throw` | 方法体里 | 主动抛出一个异常对象 |

```java
// throws：声明，自己不处理
public static void readFile(String path) throws IOException {
    // 方法里可以不 catch IOException
}

// throw：主动抛
public static void checkAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负数：" + age);
    }
}
```

**受检异常的两种处理方式：** 要么 catch 掉，要么 throws 抛给上层，二选一，编译器强制。

## 6. 自定义异常

业务里需要表达"自己的错误"，比如余额不足：

```java
// 继承 RuntimeException：非受检，用起来省事（业务校验常用）
public class InsufficientBalanceException extends RuntimeException {
    public InsufficientBalanceException(String message) {
        super(message);   // 把消息传给父类
    }
}
```

```java
// 使用
public void withdraw(double amount) {
    if (amount > balance) {
        throw new InsufficientBalanceException("余额不足，当前余额：" + balance);
    }
    balance -= amount;
}
```

**命名规范：** 类名以 `Exception` 结尾；继承哪个看语义——业务校验失败一般继承 `RuntimeException`，外部资源问题（文件/网络）继承 `Exception` 更严谨。

## 7. 常见异常速查表

| 异常 | 什么时候出现 | 排查方向 |
| --- | --- | --- |
| `NullPointerException` | 调用了 null 对象的方法/属性 | 哪个变量是 null，为什么 |
| `ArrayIndexOutOfBoundsException` | 数组下标越界 | 下标范围 0 ~ length-1 |
| `ArithmeticException` | 整数除以 0 | 除数可能为 0 |
| `NumberFormatException` | 字符串转数字失败 | 字符串里有非数字 |
| `ClassCastException` | 强转类型不对 | instanceof 先判断 |
| `FileNotFoundException` | 文件不存在 | 路径写对了吗 |
| `ConcurrentModificationException` | 遍历时修改集合 | 用迭代器 remove |

## 8. 异常处理最佳实践

1. **不要吞异常**：`catch (Exception e) { }` 空实现是反面教材，出问题完全没线索
2. **打日志**：`e.printStackTrace()` 控制台输出（生产环境用日志框架 SLF4J，后面 Spring 阶段学）；日志要包含上下文信息（哪个用户、哪个订单）
3. **不要用异常控制流程**：正常逻辑用 if 判断，异常只留给"意外情况"
4. **catch 要具体**：能捕获 `IOException` 就不要捕获 `Exception`，更不要 `catch (Throwable)`
5. **finally 里别写 return**：会吞掉 try 里的返回值



